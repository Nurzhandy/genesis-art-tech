# Регистрация, главная после входа, лендинг и починка «простой формы» — план на троих (21.11.2026)

Сдача **22.11, 23:59 по Астане**. Части A, B, C делаются параллельно, каждый в своих файлах.

## Что сейчас

- **Входа нет.** Дневник «принадлежит» тому браузеру, где лежит его id (`localStorage`, полка в `src/lib/client/diaryKey.ts`). Сервер проверяет заголовок `x-diary-key` (`ownsDiary` в `src/lib/db.ts`). Сменил браузер или телефон — дневники пропали.
- **Лендинг и рабочее место смешаны.** На главной `/` (`src/app/page.tsx`) сразу и рекламный текст, и стол с дневниками (`Desk`). Отдельной «моей» страницы нет.
- **Баг «простой формы».** На доске дня кнопка «простая форма» (`AssembleBar.tsx`) ведёт на `/diary/<id>/new` и не говорит, с какой доски пришли. Поэтому:
  - ссылка «← дневник» на форме ведёт в архив `/diary/<id>`, а не обратно на доску дня;
  - отправка формы создаёт **новый** день (`api.createDay`), а черновик доски остаётся пустым и висит на доске дневника карточкой «черновик».

## Как будет

```
гость → лендинг «/» → «Начать» → /signup (или /login)
     → вход → /home: мои дневники (стол), недавние дни, черновики, «＋ день»
     → дневник → доска → «＋ день» → доска дня ⇄ «простая форма» (туда и обратно на ту же доску)
     → «Собрать день» → страница дня
вошедший человек на «/» → сразу /home
```

## Общий контракт (A коммитит первым, ~30 минут)

Отдельный коммит `types: auth contract`, B и C работают от него.

1. `src/lib/client/auth.ts`:
   - `useAuth(): { user: { id: string; email: string } | null; loading: boolean }`;
   - `signUp(email, password)`, `signIn(email, password)`, `signOut()`; ошибки — понятным русским текстом;
   - `authHeaders(): Record<string, string>` — `Authorization: Bearer <token>`, если человек вошёл.
   Сначала заглушка (`user: null`, `loading: false`), потом настоящая реализация. B и C пользуются только этим файлом.
2. Адреса: `/signup`, `/login`, `/home`. Лендинг остаётся на `/`.
3. Локальный режим без ключей Supabase (`.local-data`): входа нет, `useAuth` отдаёт `user: null`, а `/home` работает «как гость» по полке устройства. Ничего не ломается.

## Часть A: регистрация и аккаунты

Отвечает за то, чтобы человек завёл аккаунт и видел свои дневники с любого устройства.

**Решение.** Supabase Auth, почта + пароль. Сессию держит сам `supabase-js` в браузере (клиент с anon-ключом уже есть в `src/lib/client/api.ts`), сервер проверяет токен через `supabaseAdmin().auth.getUser(token)`. Без новых зависимостей и без куки.

Чтобы не переписывать все роуты, существующая проверка `x-diary-key` остаётся. После входа полка устройства **заполняется дневниками аккаунта**, и всё, что работает сейчас, работает дальше.

1. **Supabase:** включить Email-провайдер. Для демо отключить подтверждение почты (Authentication → Providers → Email → Confirm email: off), иначе жюри застрянет на письме.
2. **Миграция 0009:** `diaries.owner_id uuid null references auth.users(id) on delete set null` + индекс. Старые дневники без владельца продолжают работать по ключу.
3. **API (новые роуты, все с `Authorization: Bearer`):**
   - `GET /api/me/diaries` — дневники, где `owner_id` = человек;
   - `POST /api/me/claim` — при первом входе привязать к аккаунту дневники с этой полки (`x-diary-key`), у которых ещё нет владельца. Чужие (с другим `owner_id`) не трогаем;
   - `POST /api/diaries` — если человек вошёл, новый дневник сразу получает `owner_id`.
4. **`src/lib/client/auth.ts`** (контракт выше). После `signIn`/`signUp`: `claim` → `me/diaries` → эти id кладутся на полку (`addToShelf`). `signOut` очищает полку устройства.
5. **Страницы `/signup` и `/login`** (`src/app/signup/page.tsx`, `src/app/login/page.tsx`, общий компонент `src/components/auth/AuthForm.tsx`):
   - поля: почта, пароль (не короче 6), на регистрации — имя (уходит в `user_metadata.name`, B покажет его на главной);
   - понятные ошибки: «такая почта уже есть — войдите», «неверная почта или пароль», «нет сети»;
   - кнопка «показать пароль», блокировка кнопки на время запроса, Enter отправляет форму;
   - после успеха → `/home` (или на адрес из `?next=`);
   - в духе дневника: бумага, рукописный заголовок, без «корпоративной» формы; работает на телефоне.
6. **Защита страниц:** `/home` и создание дневника — только после входа (проверка на клиенте через `useAuth`, без входа → `/login?next=...`). Демо-дневник и ссылки-подарки `/s/...` открываются без входа.
7. **Тесты:** `claim` не забирает чужие дневники; `me/diaries` без токена — 401; `POST /api/diaries` с токеном ставит владельца.

**Готово, когда:** зарегистрировался на одном браузере, создал дневник, вошёл в другом браузере — дневник на месте и редактируется.

**Честно о безопасности:** ключ дневника по-прежнему равен его id. Это не хуже, чем сейчас, но и не лучше. Если останется время — проверять владельца по токену в `assertCanEdit` (отдельная задача, не обязательна к сдаче).

## Часть B: главная страница после входа (`/home`)

Отвечает за место, куда человек попадает каждый день.

1. **Роут `/home`** (`src/app/home/page.tsx`, компоненты в `src/components/home-app/`):
   - шапка: «Привет, <имя>», дата сегодня, меню профиля (почта, «выйти»);
   - **стол с дневниками** — переносим `Desk` с лендинга сюда как есть (книги, открытие книги, «＋ новый дневник»);
   - **«Продолжить»:** незаконченные черновики дней (доска без сборки) — карточки «черновик» с переходом на `/day/<id>/board`. Брать из `daysWithDrafts` (`src/lib/client/dayBoard.ts`) по каждому дневнику полки;
   - **«Недавние дни»:** последние 6 собранных дней всех дневников — постеры-превью со ссылкой на страницу дня;
   - **быстрый «＋ день»:** если дневник один — сразу черновик и доска дня (`NewDayButton`), если несколько — выбор дневника.
2. **Пустое состояние** для нового аккаунта: «Заведите первый дневник» + кнопка, рядом демо-дневник примером.
3. **Навигация:** ссылка «← стол» на досках (`Board.tsx` → сейчас ведёт на `/`) и в архиве ведёт на `/home`. Список мест: `grep -rn 'href="/"' src`.
4. **Телефон:** одна колонка, стол прокручивается, кнопки крупные.
5. Без входа `/home` → `/login?next=/home` (см. A6). В локальном режиме — по полке устройства.

**Готово, когда:** после входа человек видит свои дневники, черновики и недавние дни, из каждого блока переходит куда нужно; новый аккаунт видит понятное пустое состояние.

## Часть C: лендинг и починка функционала

Отвечает за первое впечатление и за то, чтобы путь создания дня не ломался.

### C1. Лендинг `/` (`src/app/page.tsx`, `src/components/home/*`)

1. **Стол уходит на `/home`** (переносит B). На лендинге вместо него — показ продукта: `MemoryMachine` / лента демо-дней, без возможности что-то сломать.
2. **Шапка:** логотип-название, «Демо», «Войти», кнопка «Начать бесплатно» → `/signup`.
3. **Первый экран:** заголовок, одна фраза о сути («день — запись, фото, песня и голос — становится живой страницей»), две кнопки: «Начать» (`/signup`) и «Смотреть демо» (`/diary/demo`).
4. **Блоки ниже:** как это работает (3 шага — обновить тексты под доску: заметки, фото, песня, голосовое, настроение), лента примеров, финальный призыв «Каким был ваш день?» → `/signup` (сейчас кнопка «К столу ↑» ведёт на якорь `#desk`, которого после переноса не будет).
5. **Убрать служебное:** ссылку «лаборатория стиля» (`/lab`) с лендинга (страница остаётся по прямой ссылке).
6. **Вошедший человек** на `/` сразу уходит на `/home` (через `useAuth`).
7. Проверить на телефоне (375 px) и в тёмной теме: без горизонтальной прокрутки, читаемые кнопки.

### C2. «Простая форма» возвращает на ту же доску и заполняет тот же день

1. `AssembleBar.tsx`: ссылка → `/diary/<diaryId>/new?draft=<dayId>`.
2. `src/app/diary/[diaryId]/new/page.tsx`: если есть `draft`, ссылка «назад» ведёт на `/day/<draft>/board` с подписью «← доска дня», а форма получает `draftId`.
3. `DayForm.tsx` с `draftId`: **не создаёт новый день.** Форма раскладывает введённое на доску черновика и собирает его:
   - текст → заметка, фото → загрузка через `api.dayBoardUpload(draftId)` и элементы `photo`, песня → элемент `song`, чувства → капля `mood`;
   - то, что уже лежало на доске, остаётся, новое ложится рядом (`api.dayBoard` → дописать → `api.saveDayBoard`);
   - дальше `api.assembleDay(draftId, …)` (признаки фото — как в `prepareAssembly` из `AssembleBar.tsx`) → переход на `/day/<draftId>`.
   В итоге черновик не висит пустым, а день один.
4. Голосовое из формы (`StoryRecorder` с «сохранить мою запись») — тоже на доску черновика как элемент `voice`.
5. Тест: из формы с `draftId` не вызывается `createDay`; заметка, фото и песня оказываются на доске черновика.

### C3. Прогон всего пути руками (последние 2 часа, вместе)

Лендинг → регистрация → `/home` → новый дневник → доска → «＋ день» → доска дня (заметка, фото, песня, голосовое, настроение) → «простая форма» → «назад» (та же доска, ничего не пропало) → «Собрать день» → страница дня → «← стол» → `/home` (день в «недавних»). Потом выйти, войти в другом браузере — всё на месте. Записать найденное и починить.

**Готово, когда:** лендинг ведёт на регистрацию и демо, вошедший попадает на `/home`, а из «простой формы» человек возвращается на свою доску и собирает тот же день.

## Правила

- Каждый в своих файлах. Общие: `auth.ts` меняет только A, `Desk.tsx` переносит только B, `AssembleBar.tsx` и `DayForm.tsx` трогает только C.
- `git pull` перед каждым блоком, маленькие коммиты, пуш в `main` после зелёных `npm test`, `npx tsc --noEmit`, `npx eslint src`.
- **Выкатка на прод — через `vercel deploy --prod`.** Автодеплой по push сейчас блокируется: Vercel не находит Git-аккаунт автора коммитов. Чтобы push выкатывался сам, каждому привязать свою git-почту (`git config user.email`) к аккаунту Vercel/GitHub.
- Перед правками Next.js читать `node_modules/next/dist/docs/` (см. `AGENTS.md`): у этой версии свои правила.
