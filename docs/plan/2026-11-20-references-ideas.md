/** Погода дня (#3). Источник — Open-Meteo archive по дате и координатам города. */
export interface DayWeather {
  tempC: number;            // средняя за день
  precipitationMm: number;  // сумма осадков

  cloudCover: number;       // 0..100, средняя облачность

## Часть A — данные и API

✅ **A1. Погода (#3).** `src/lib/weather.ts`: `geocode(place): Promise<{lat, lon, name} | null>`
(`https://geocoding-api.open-meteo.com/v1/search?name=…&language=ru&count=1`) и
`dayWeather(lat, lon, date): Promise<DayWeather | null>`
(`https://archive-api.open-meteo.com/v1/archive?…&daily=temperature_2m_mean,precipitation_sum,snowfall_sum,cloud_cover_mean`;
для дат за последние 5 дней — `api.open-meteo.com/v1/forecast` с `past_days`). Таймаут 5 с, любой сбой → `null`.
В форме необязательное поле «Город» (запоминается в localStorage). В `NewDayInput` + `place?`.
В `generateDay` погода считается до `buildStyle` и передаётся в `StyleInput.weather`, сохраняется в `days.weather`.
Тесты: разбор ответа Open-Meteo из фикстуры; сбой сети → `null`; дата сегодня → forecast-эндпоинт.

✅ **A2. EXIF (#4).** В `processPhoto` читаем `DateTimeOriginal` (маленький парсер APP1 без библиотек
или `exifr` — решает A). Если у всех фото одна дата, а в форме другая — подсказка «Фото сделаны 18 октября — поставить эту дату?».
Час съёмки передаём в генерацию как `photoHour?: number` → `fallbackAnalysis` и промпт («снято в 19:40»).
Тесты: парсер на двух JPEG-фикстурах (с EXIF и без).

✅ **A3. Обложка альбома в генерацию (#2, интеграция).** В `SongInput` после `resolveSong`, если есть
`coverUrl`, вызвать `extractCoverPalette(coverUrl)` от B и положить в `music.coverPalette`.

✅ **A4. Поделиться днём (#6).** `POST /api/days/[id]/share` (только владелец, `x-diary-key`) создаёт
`share_id` (nanoid 10), `DELETE` отзывает. Страница `/s/[shareId]` — только просмотр дня (без
папки, правок и ключа), `generateMetadata` с `og:image` = постер. Кнопка «Поделиться» на странице
дня: копирует ссылку, показывает QR (`qrcode` или свой SVG). Тесты: только владелец создаёт;
отозванная ссылка → 404; ответ `/s` не содержит `diaryId`.

✅ **A5. Капсула времени (#12).** Чекбокс в форме «Запечатать до…» (дата > сегодня). `GET` дня до
`sealed_until` отдаёт только дату, название и `sealedUntil` (без текста, фото, стиля). В архиве —
карточка-конверт «Откроется 19.11.2027». Тесты: запечатанный день не отдаёт текст/фото; после даты отдаёт всё.

✅ **A6. Все дни песни (#13).** `GET /api/diaries/[id]/days?song=<key>`, где key = `provider:id` или
`artist — title` в нижнем регистре. Ссылка с названия песни на странице дня. Тест: ключ из SongRef.

**Как сделана часть A (20.11, выполнили за друзей):**
- Миграция `0003_references.sql` применена; кроме плана добавлена колонка `place` (город записи), по ней
  `generateDay` спрашивает погоду параллельно с анализом. Погода есть и в «Не совсем так?», и в превью.
- Цвета обложки идут отдельным полем `GenerateBody.coverPalette` (а не только в `music`): у ссылок без
  данных Deezer `music` бывает `null`. В форме под песней видны три кружка цветов обложки.
- EXIF: свой парсер APP1 (`src/lib/client/exif.ts`), HEIC без EXIF. Час съёмки → `photoHour` → промпт
  («Фото сняты около 19:00») и запасной анализ; слова записи о времени суток важнее часов камеры.
- Подарок: **пути в Storage начинаются с id дневника (ключа владельца)**, а подписанная ссылка содержит путь.
  Поэтому при «Поделиться» файлы дня копируются в `_shared/<shareId>/`, гость получает ссылки только на копии,
  постер для превью — через `/s/<id>/poster`. Отзыв ссылки и удаление дня удаляют копии. QR не делали:
  на телефоне кнопка открывает системное «Поделиться».
- Капсула: сервер отдаёт запечатанный день как `sealedView` (`sealed: true`, без текста, фото, песни, стиля);
  закрыты также `/files`, `/voice`, `restyle` и подарок. «Сегодня» считаем по Астане.
- Дни песни: у песни несколько ключей (`исполнитель — название` и `сервис:id`), фильтр принимает несколько
  `song=`, поэтому день с названием и день только со ссылкой на тот же трек находят друг друга.

## Часть B — визуал и звук (наша)

✅ **B1. Погода и обложка в правилах (#2, #3).** `buildAtmosphere`: осадки ≥ 1 мм и tempC > 0 → `rain`;
снег ≥ 0.5 см или осадки при tempC ≤ 0 → `snow` (погода важнее слов записи, но слова «дождь» без
погоды по-прежнему работают). `buildPalette`: tempC ≤ −5 → +0.15 к холодному сдвигу, ≥ 25 → +0.1
к тёплому; облачность ≥ 80 → −10% насыщенности. Обложка: 12% подмешивания `coverPalette[0..2]`
в акценты. Причины: «В тот день в Астане шёл дождь (4 мм) → капли», «Обложка альбома добавила
янтарный». Тесты в `buildStyle.test.ts`.

✅ **B2. Прокси обложки и извлечение палитры (#1, #2).** `GET /api/music/cover?url=` — только хосты
обложек (`*.dzcdn.net`, `i.scdn.co`, `i.ytimg.com`, `*.mzstatic.com`), иначе 400 (защита от SSRF),
кэш 1 день. Клиент: `extractCoverPalette(coverUrl): Promise<string[]>` (через прокси → canvas →
`computeFeatures`). Нужен ещё и рендеру: обложка на пластинке без «грязного» canvas.
Тесты: разрешённые/запрещённые хосты.

✅ **B3. Марка и штампы из данных (#17, S4).** Постоянный элемент у всех дней: почтовая марка сезона
в правом верхнем углу фото-зоны (зубчатый край, цвет `accents[1]`, глиф сезона) и круглый штемпель
с датой. Рядом бирки только из анализа: погода (из `weather`, иначе сезон и время суток), место
(`setting`), люди (`people`). Форма штампа зависит от техники: геометрия — квадрат, плёнка —
бумажный билет, остальное — круг. Правило `buildStamps(input)` → `StyleParams.stamps` с причиной.
Тесты: набор бирок для фикстур, у нейтрального дня только дата и сезон.

✅ **B4. Звуки (#8, #16).** Всё процедурно на Web Audio — без скачанных файлов и прав:
дождь (розовый шум + капли), снег/тишина (тихий ветер), листья (ветер + шорох), пар (низкий гул),
огни (далёкий город), пыль (тихий треск плёнки). `soundscapeFor(kind)` → рецепт; громкость 12%
от музыки, приглушается под озвучку вместе с музыкой; кнопка «звуки дня» вкл/выкл.
Звук перелистывания (короткий отфильтрованный шум) — в книге и при «Открыть день».
Тесты: рецепт для каждого `AtmosphereKind`, громкости в пределах.

✅ **B5. Страница собирается на глазах (S3).** При «▶ Открыть день» элементы появляются по одному
в долю: фото, затем скотч и марка, затем заметки на полях, затем подпись и предмет-песня. Темп —
BPM, число долей на сборку — по энергии (2–8), резкость появления — по напряжению. На постере всё
собрано. Чистая функция `assemblyAt(t, style)` → прозрачность каждого слоя; тесты на порядок и
длительность. Плюс звук перелистывания из B4 при листании книги друга (S1).

## Часть C — интерфейс, экспорт, сдача

**C1. Обои (#5).** Кнопка «Обои на телефон» на странице дня: постер 1080×1920 и вариант без текста
(`engine.renderAt` с флагом `noText` — B добавляет флаг в `drawConstants` по запросу C).

**C2. Видео (#7, #19).** «Скачать видео 15 / 30 / 60 с»: `canvas.captureStream(30)` +
`MediaRecorder` (webm/mp4 по поддержке), звук — свой файл или превью Deezer через `AudioContext`
`MediaStreamDestination`. Для embed-песен видео без звука с пометкой.

**C3. Конверт (#11).** Вариант ритуала: день приходит в конверте с маркой сезона (из B3), клапан
открывается → письмо с текстом дня → воспоминание. Включается для дней из «В этот день» и капсул.

**C4. Год в цветах (#14).** `/diary/[id]/year/[yyyy]`: 365 клеток по `dayColor`, «песня года»
(самая частая), «самая тёплая неделя», скачать PNG. Без «анализа настроения».

**C5. Свой голос (#15).** Кнопка 🎙 «Записать своим голосом» на странице дня (MediaRecorder,
до 2 мин) → upload kind `voice` → `voice.path`, `preset.because = 'ваш голос'`. В плеере свой голос
важнее синтеза. Нужен kind `voice` в `UploadRequest` (C добавляет вместе с тестом).

**C6. Стопка фото (#18).** Оригиналы фото стопкой полароидов на странице дня, свайп листает.

**C7. Сдача.** 5–7 настоящих любимых дней команды в демо-дневнике (`scripts/seed-demo.ts`),
видео до 3 минут по [сценарию](../submission/video-script.md) с кадрами книги и пластинки,
`docs/submission/examples/`, обновить `description.md`, `techniques.md`, `tools.md` (Open-Meteo).
