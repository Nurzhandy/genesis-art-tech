# День как пустая доска — план на троих (21.11.2026)

## Идея

Сейчас «＋ день» открывает форму с полями: дата, город, текст, чувства, фото, песня, капсула.
Вместо неё открывается **пустая доска дня**, такая же свободная, как доска дневника. На ней человек:

- пишет заметки с идеями и воспоминаниями;
- прикрепляет фото;
- добавляет песни, которые ассоциируются с днём (пластинки);
- рисует кистью и клеит стикеры;
- ставит **настроение дня** — каплю-чувство из трекера эмоций.

Внизу доски кнопка **«Собрать день»**. Она превращает всё, что лежит на доске, в живую страницу дня: постер, атмосферу, анимацию.

Ничего не обязательно, кроме того, что на доске должно лежать хоть что-то: заметка, фото или песня.

## Как это будет работать

```
доска дневника → «＋ день» → сразу создаётся черновик дня → /day/<id>/board (пустая доска с подсказками)
   → человек кладёт заметки, фото, песни, рисунки, стикеры, настроение (автосохранение)
   → «Собрать день» → из доски собираются данные → прежний generateDay → /day/<id>
   → на странице дня: живая страница + «доска дня» (то, что человек собрал руками)
```

Из доски в генерацию идёт:

| На доске | Во что превращается |
|---|---|
| заметки (сверху вниз, слева направо) | `text`: текст дня для анализа |
| фото (первые 5 по порядку) | `photoFeatures` и файлы дня |
| первая песня | `song` и `music` (остальные песни просто лежат на доске) |
| настроение (капля-чувство) | `feeling` |
| дата и город в шапке доски | `date`, `place` |
| рисунки и стикеры | `decor`: переносятся на постер (масштаб доски → холст 1080×1920) |
| стрелки, рамки | остаются на доске дня |

Старая форма остаётся запасным путём по ссылке «простая форма», пока доска не станет стабильной. Она же нужна на телефоне, если доска будет неудобной.

## Общий контракт (делаем в первую очередь, вместе, ~30 минут)

Человек 1 коммитит его первым отдельным коммитом `types: day board`, остальные работают от него.

1. `src/lib/board/board.ts`: новый тип элемента
   `mood { id, x, y, rot, feelings: string[] (до 3 id из FeelingPicker), size }`.
   Тот же `BoardSchema` используется и для доски дневника, и для доски дня.
2. `src/lib/board/collect.ts`: чистая функция `collectDay(board) → { text, photoPaths[], song | none, feeling | undefined, decor }`.
   Порядок заметок: по `y`, при равных по `x`. Пишется с тестами.
3. API доски дня (форма запросов как у доски дневника):
   - `GET /api/days/[dayId]/board`: доска и подписанные ссылки на фото;
   - `PUT /api/days/[dayId]/board`: сохранить (только владелец, ≤ 600 КБ, фото только из папки этого дня);
   - `POST /api/days/[dayId]/board/upload`: подписанная загрузка фото;
   - `POST /api/days/[dayId]/assemble`: собрать день из доски.

## Человек 1: данные и сервер

Отвечает за то, чтобы доска дня хранилась и превращалась в день.

1. **Миграция 0006:** `days.board jsonb` (null = доски нет, старые дни), применить в Supabase.
   Пустой черновик: `text` может быть пустым у `status = 'draft'`.
2. **Черновик сразу:** `POST /api/diaries/[id]/days` с одной датой создаёт пустой черновик.
   `NewDayInput` получает вариант `{ date, draft: true }`.
3. **Роуты доски дня** (см. контракт). Код берётся из `/api/diaries/[diaryId]/board` с проверкой `ownsDiary` через `diaryId` дня.
4. **`collectDay` + тесты** (`src/lib/board/collect.test.ts`): порядок заметок, ограничение в 5 фото, первая песня, пустая доска даёт ошибку «положите на доску хоть что-то».
   Рисунки и стикеры с доски переводятся в `decor` дня: рамка всех элементов вписывается в холст 1080×1920, кисть с сиянием сохраняет `glow`.
5. **`POST /api/days/[dayId]/assemble`:**
   - берёт доску и вызывает `collectDay`;
   - копирует фото доски в слоты `photo(i)` и `thumb(i)` дня;
   - записывает `text`, `song`, `feeling`, `place`;
   - вызывает существующий `generateDay`, признаки фото присылает браузер.
6. **Повторная сборка:** если человек поменял доску после сборки, «Пересобрать день» сбрасывает статус и собирает заново (лимит генераций в сутки тот же).
7. Локальный режим без Supabase (`.local-data`) должен работать с новой колонкой.

**Готово, когда:** через curl можно создать черновик, положить доску с заметкой и фото, вызвать assemble и получить готовый день; тесты зелёные.

## Человек 2: редактор доски

Отвечает за то, чтобы на доске было приятно творить.

1. **Вынести ядро из `Board.tsx`** (сейчас 468 строк) в `BoardCanvas`: панорама и зум, инструменты, отмена, удаление, автосохранение.
   Снаружи передаются `load`, `save`, `upload` и набор инструментов.
   Доска дневника продолжает работать как раньше: проверить руками.
2. **Новый инструмент «Настроение» (M):**
   - ставит на доску каплю с чувствами;
   - по клику открывается `FeelingPicker` от друга, можно выбрать до 3 чувств;
   - капля окрашивается в цвет зоны (можно взять `MoodBlob`).
3. **Роут `/day/[dayId]/board`:**
   - шапка: дата (можно сменить) и город (по желанию, подставляется из GPS фото);
   - пустое состояние с 3 подсказками прямо на доске, которые исчезают после первого элемента: «двойной щелчок — заметка», «перетащите фото», «♪ — песня дня»;
   - при первом входе доска влетает той же анимацией, что из книги.
4. **Голос:** кнопка «рассказать голосом» (компонент друга из формы) кладёт расшифровку на доску новой заметкой.
5. **Телефон:** щипок двумя пальцами для зума, крупные кнопки панели.

**Готово, когда:** на `/day/<id>/board` можно положить все 7 видов элементов, они сохраняются и переживают перезагрузку; доска дневника не сломалась.

## Человек 3: сборка дня, переходы и подача

Отвечает за путь «пустая доска → живая страница» и за то, что увидит жюри.

1. **«＋ день» на доске дневника:** создаёт черновик (API человека 1) и переходит на `/day/<id>/board`.
   Карточка-черновик сразу появляется на доске дневника с подписью «черновик».
2. **Кнопка «Собрать день»:**
   - перед отправкой считает признаки фото в браузере (`PhotoPicker` уже умеет это из файла);
   - вызывает assemble;
   - показывает `GenerateProgress`.
   Если доска пустая, мягко подсказывает, что положить.
3. **Анимация сборки (вау-момент):** элементы доски слетаются в центр и «впитываются» в постер.
   Заметки складываются в текст, фото в рамку, пластинка начинает крутиться. Затем переход на `/day/<id>`.
4. **Страница дня:**
   - вкладка или блок «доска дня» с доской только для просмотра под живой страницей;
   - кнопки «изменить доску» и «пересобрать день».
5. **Старая форма** уходит за ссылку «простая форма» на доске дня. Ничего не удаляем до демо.
6. **Демо:**
   - собрать 2–3 дня демо-дневника через доску (с рисунками и стикерами);
   - снять этот путь для видео: стол → книга → доска дневника → «＋ день» → пустая доска → «Собрать день» → живая страница.

**Готово, когда:** весь путь проходит руками без ошибок на проде, есть хотя бы один демо-день, собранный с доски.

## Правила, чтобы не мешать друг другу

- Каждый работает в своих файлах. Общий только `board.ts`, его меняет человек 1 и только через контракт.
- Перед началом каждого блока делать `git pull`, коммиты маленькие, пуш в `main` после зелёных `npm test` и `npx tsc --noEmit`.
- Главную со столом и анимацию открытия книги не трогаем, это наша концепция.
- Выкатка на прод одна, в конце, после общего прогона.
