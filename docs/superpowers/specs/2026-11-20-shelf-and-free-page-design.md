# Полка дневников и свободная страница (гибрид А)

Дата: 20.11.2026. Дедлайн сдачи: 22.11, 23:59 по Астане.

## Зачем

Сайт ощущается «зажатым»: один дневник, одна форма, страница целиком решается системой. Человек хочет
**творческое пространство**: заводить сколько угодно дневников под разные сферы (воспоминания, путешествия,
работа, инсайты), и на странице дня **добавлять своё**: стикеры, текст, рисунок. Если времени нет —
**наговорить**, и страница соберётся сама. Цель та же, что у всего проекта: через недели и месяцы открыть
запись и снова почувствовать тот день.

## Цели

1. **Полка дневников.** Сколько угодно дневников на устройстве, у каждого название и вид
   (воспоминания, путешествия, работа, инсайты, свой). Первый экран — «стол»: пустое пространство,
   где лежат дневники и слот «+ новый дневник».
2. **Свободная страница дня.** Поверх собранного системой воспоминания человек кладёт стикеры, пишет
   рукописные заметки и рисует кистью. Всё сохраняется и видно везде: плеер, постер, обои, видео, книга, подарок.
3. **Быстрый путь.** Наговорил день → система сама собирает страницу **и сама раскладывает стикеры** по
   правилам (кофе в записи → чашка, дождь → капля, осень → лист), с причиной в «Почему так».

## Не цели (до дедлайна)

- Бесконечная доска без системы (вариант Б), загрузка своих картинок-стикеров, текст без фото и песни,
  синхронизация полки между устройствами одним входом, совместные дневники.

## Анти-цели (провал, даже если работает)

- Лента перестаёт выглядеть как дневник одного человека: стикеры и кисть в случайных цветах, эмодзи,
  которые на каждом телефоне выглядят по-разному. Поэтому **цвета стикеров, текста и кисти — только из палитры дня**,
  стикеры — наш собственный нарисованный набор.
- Сломать то, что уже работает и оценивается: генерацию, правила, «Почему так», папку дня, архив, подарок, капсулу.

## Ограничения

- ТЗ: вход «текст + минимум одно фото + песня», воспоминание строится из ввода по правилам, песня влияет,
  папка с названием, архив, единая визуальная система. Всё это остаётся обязательным во всех видах дневников.
- Логина нет: ключ дневника = его id (заголовок `x-diary-key`), так и остаётся.
- Около 50 часов до сдачи: только нативный CSS / Canvas, без новых библиотек.

## Подходы

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| **А (выбран)** | Гибрид: полка дневников + система собирает страницу, человек дополняет поверх; AI-путь голосом и авто-стикеры | Сохраняет баллы за систему (40 из 100), даёт свободу, ~1 день работы | Свобода ограничена слоем поверх страницы 9:16 |
| Б | Полностью свободная доска (как Miro) | Максимум свободы | Система перестаёт превращать настроение в форму, сырой результат к дедлайну |
| В | Сейчас только полка, доска к финалу | Минимум риска | Нет главного — творческой свободы |

Выбран **А** (решение человека).

## Как устроено

### Полка (несколько дневников)

- Миграция `0004_shelf_decor.sql`: `diaries.title text`, `diaries.kind text` (`memories | travel | work | insights | custom`),
  `days.decor jsonb`.
- API: `POST /api/diaries { title, kind }`; `GET /api/diaries?ids=a,b,c` — карточки полки (название, вид,
  число дней, последний постер/цвет); `PATCH /api/diaries/[id] { title }` — только владелец.
- Ключи на устройстве: список `atmosphere-shelf` в localStorage (старый одиночный ключ переносится в него).
  Владелец = id дневника есть в этом списке; заголовок `x-diary-key` берётся для конкретного дневника.
  Перенос на другое устройство: у каждого дневника своя ссылка-ключ (как сейчас) плюс «ссылка на всю полку»
  `/?shelf=id1,id2…` с предупреждением, что это ключи ко всем дневникам.
- Вид дневника меняет: обложку на полке и в книге (цвет, иконка), подсказку в форме записи
  («Что запомнилось в дороге?», «Какой инсайт дня?»), название по умолчанию. Правила стиля не меняются.

### Первый экран — «стол»

- `/`: на бумажном столе лежат дневники человека (обложки с названием, числом дней, цветом последнего дня),
  слот «+ новый дневник» и демо-дневник как пример. У нового человека стол пустой, только слот и пример.
- Создание дневника: название и вид → дневник появляется на столе с анимацией «положили на стол».
- «Машина воспоминаний», бегущая строка и лента пяти дней остаются ниже как «как это работает».

### Свободная страница дня

- Кнопка «✎ Украсить страницу» у владельца. Режим редактора поверх холста 9:16:
  - **Стикеры** — свой набор нарисованных SVG-форм (~16): скотч, звезда, сердце, лист, снежинка, солнце,
    цветок, капля, облако, чашка, нота, билет, стрелка, искра, марка, сердечко-печать. Перетащить, повернуть,
    изменить размер, удалить.
  - **Текст** — рукописная заметка шрифтом дневника (Caveat), наклон.
  - **Кисть** — рисунок пальцем или мышью, 3 толщины.
  - Цвета — только 5 цветов палитры дня (чернила, бумага, 3 акцента).
  - «Отменить», «Очистить», «Сохранить».
- Хранение: `days.decor = { v: 1, items: [...] }`, координаты в системе холста 1080×1920, цвет — ссылка на
  цвет палитры (`ink | paper | a0 | a1 | a2`): после «Не совсем так?» украшения перекрашиваются вместе с днём.
  Лимиты: до 40 элементов, штрих до 400 точек, весь decor до 64 КБ. `PUT /api/days/[id]/decor` — только владелец,
  валидация zod, сброс постера (плеер нарисует новый), файл `decor.json` в папке дня.
- Рендер: движок рисует слой украшений после подписи и заметок, до зерна, — поэтому он есть в постере, обоях,
  видео, книге и на странице подарка. В сборке страницы появляется вместе с подписью.

### Быстрый путь и авто-стикеры

- В форме записи крупная кнопка «🎙 Наговорить день» (диктовка уже есть) — сразу видна первой.
- Правило `autoDecor(analysis, style)`: 2–4 стикера по записи — сезон, сенсорные детали (кофе/чай/какао → чашка,
  дождь → капля, музыка → нота, море → волна…), время суток (ночь → звёзды). Раскладываются в свободные места
  полей (не на фото и не на подпись). Ставятся при генерации, если человек ещё ничего не украшал.
  Причина в «Почему так»: «Стикеры: «какао» в записи → чашка, осень → лист».

## Что остаётся исполнителю

Точные формы и названия стикеров, расклад авто-стикеров по полям, вид обложек на столе, тексты подсказок
по видам дневников, детали жестов редактора (поворот двумя пальцами — по возможности, иначе ручка поворота).

## Порядок

1. Миграция, API дневников, полка в localStorage, владелец по списку (тесты).
2. «Стол» на главной, создание и переименование дневника, вид дневника в архиве и книге.
3. Модель decor, стикеры (Path2D), рендер в движке, API сохранения (тесты).
4. Редактор страницы.
5. `autoDecor` + причина (тесты), кнопка «Наговорить день».
6. Проверка в браузере, деплой — по согласию.
